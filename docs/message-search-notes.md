# 메시지 · 검색 화면 재작업 노트 (feature/message-search)

목업(검색 팝업 오류창 / 검색 시 화면 / 메시지 / 메시지 2 / 1:1 대화창 / 메세지 3 / 방명록 검색 활성)
기준으로 UI + 목업 데이터로 구현. 백엔드 연동 전 프로토타입 단계.

## 구현 완료

### 검색 (Search)
- **기본 화면**: 정렬 버튼 제거. `MockDataSource.searchDefaultFeed()` = 생전/사후/메모리얼 히스토리 게시글 중 무작위 3개.
- **검색 시 화면**: 이름 입력(`query` 非공백) 시에만 `좋아요순/조회순/조화많은순` 버튼 노출.
  결과는 사용자/메모리얼 카드 리스트. `이수진` 동명이인 3인 케이스 포함.
- **결과 카드**(`MemorialProfileItem`): 아바타 + (故) 이름 + 조화수 + 우측 버튼.
  - `hasProfile` → `프로필`(테두리 버튼), `hasMemorial` → `메모리얼`(파랑 버튼)
  - `isDeceased` → 이름 앞 `故`
- **정렬**: `likeValue` / `viewValue` / `flowerValue` 내림차순. 현재 Mock 수치.
- **검색 팝업 오류창**: 버튼이 검색 후에만 뜨므로 불필요 → 만들지 않음.

### 메시지 (Message)
- 상단 검색창은 입력창이 아니라 **버튼**. 탭에 따라 이동:
  - 메시지 탭 → `message/search` (추천 더보기)
  - 방명록 탭 → `message/guestbook_search`
- 방명록 탭 상단에 `내가 남긴 방명록 기록` 라벨 추가.
- **메시지 2 (추천 더보기)**: 뒤로가기 + 검색필드 + `추천 더보기` 목록, X로 개별 제거(로컬).
  데이터: `MockDataSource.messageSuggestedUsers`.
- **방명록 검색 활성**: 뒤로가기 + 검색필드(X 클리어). 입력/삭제마다 실시간 필터:
  (고인 이름 포함) OR (방명록 내용 포함), 최신순(`daysAgo` 오름차순). 일치어 파랑 볼드.
  `미소` 검색 시 `故 이철수`, `故 김미소` 노출되도록 목업 데이터 추가.
- **1:1 대화창**: 시안 대화 재현(`chat_1` = 김민수). 전송 시 로컬 목록에 즉시 추가(데모).
  우상단 달력 아이콘은 표시만.

## 미해결 / stub (연동 필요)

| 위치 | 현재 | 필요 |
|---|---|---|
| 추천 더보기에서 유저 탭 | `onUserClick` 빈 콜백 | 해당 사용자 **프로필 화면**으로 이동 (라우트 미정) |
| 방명록 검색 결과 탭 | `onResultClick` 빈 콜백 | 내 댓글이 있는 **추모 페이지 방명록 화면**으로 이동 |
| 메시지 탭 방명록 아이템 탭(`ClickGuestBook`) | 빈 콜백 | 위와 동일 화면으로 이동 |
| 정렬 수치(`likeValue`/`viewValue`) | Mock 상수 | 좋아요순 = 프로필 전체 게시글 + 메모리얼 히스토리 게시글 좋아요 합 / 조회순 = 프로필 조회수 + 메모리얼 조회수 |
| 검색 결과 데이터 | `memorialSearchItems` 필터 | 실제 유저/메모리얼 통합 검색 API |
| 추천 더보기 데이터 | 하드코딩 4명 | 추천 알고리즘 (그리고 애초에 메시지 화면에 추천더보기가 필요한지 재확인) |
| 대화창 메시지 | 목업 대화, 전송=로컬 | 실제 메시지 송수신 |
| `ClickWriteAction` (우상단 작성 버튼) | 빈 콜백 | 동작 미정 |
| 대화창 카메라/마이크/이미지/+ 아이콘 | 표시만 | 동작 미정 |

## 열린 질문
- 메시지 화면에 "추천 더보기"가 왜 있는지 기획 확인 필요 (사용자도 불확실).
- 방명록 검색의 검색필드 placeholder가 목업에 `메시지`로 되어 있음 — 의도된 문구인지 확인.
